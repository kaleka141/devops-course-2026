1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

В Git ветка — это просто указатель (лёгкий файл со ссылкой на коммит), создание новой ветки происходит мгновенно и не копирует файлы физически. В SVN ветка технически реализована как полная копия директории проекта на сервере (svn copy). Это значит, что создание ветки требует копирования всех файлов, занимает время и место на диске, особенно на больших проектах.

2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — централизованная система: у разработчика хранится только рабочая копия файлов, а вся история изменений находится на одном центральном сервере. Коммит — это отправка изменений сразу на сервер, поэтому без подключения к нему закоммитить невозможно. В Git, наоборот, у каждого разработчика есть полная копия репозитория со всей историей, поэтому коммиты делаются локально, а на сервер (push) отправляются уже потом, когда появится интернет.

3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

В legacy-проектах, которые изначально были на SVN, и переход на Git экономически нецелесообразен (особенно в госсекторе и банках со строгими регламентами). Когда нужен жёсткий централизованный контроль доступа на уровне отдельных папок/файлов (SVN это умеет из коробки, в Git — сложнее). При работе с очень большими бинарными файлами без специальных расширений вроде Git LFS — модель "один сервер, частичная выгрузка" иногда удобнее, чем полная копия истории у каждого разработчика.
